# 날짜별 밥상과 지난 날짜 기록 추가

변경 버전: 1.0.2 (14)

- 캘린더에서 날짜를 누르면 메인과 같은 아침/점심/저녁 사진 배치를 사용합니다.
- 같은 끼니의 사진은 사람별 고정 자리로 나란히 보입니다. 작은 화면과 큰 글씨에서는 기존 접근성용 한 열 표시를 유지합니다.
- 사진이 있는 날과 없는 과거 날짜 모두 ‘이날 사진 추가하기’ 및 끼니별 ‘+ 남기기’를 사용할 수 있습니다.
- 올리기 화면에 기록할 날짜를 표시하고, 저장 후 같은 날짜의 밥상을 다시 엽니다.
- 로컬 기록과 공유 기록 모두 선택한 날짜를 보존합니다. 기존 공유 기록은 종전 생성 시각으로 읽어 호환성을 유지합니다.
- 공유 기록의 실제 업로드 시각(createdAt)은 계속 서버 시각을 사용하며, 기록 날짜(recordedAt)만 별도로 저장합니다. 기존 알림의 업로드 작성자/시각 검증은 변경하지 않습니다.

## 적용 순서

1. 앱 소스와 함께 수정된 Firestore 규칙을 배포합니다. 이 작업은 기존 기록을 삭제하거나 이전하지 않습니다.
2. 새 앱을 빌드해 설치합니다. 함께 쓰는 기기도 새 버전으로 업데이트해야 새 기록 날짜를 일관되게 표시합니다.

맥 터미널(소스 패치 적용 후):

```sh
cd ~/Documents/mwomeogeo-build12
npx --yes firebase-tools@15.34.0 login --reauth
npx --yes firebase-tools@15.34.0 deploy --only firestore:rules --project mwomeogeo
flutter pub get
flutter build ipa --build-name=1.0.2 --build-number=14
open build/ios/archive/Runner.xcarchive
```

현재 운영 Firestore 규칙 배포, iOS 빌드 및 설치는 아직 완료하지 않았습니다. GitHub 연결의 쓰기 권한 오류(403)로 저장소 반영도 되지 않았습니다.

## 검증 결과

- Flutter 변경 파일/테스트 정적 분석: 이상 없음
- Flutter 테스트 34개 통과(날짜별 나란히 보기, 과거 날짜 업로드 후 같은 날짜 재표시, 로컬 재실행 후 날짜 유지 포함)
- Firestore 보안 규칙 검사 69개 통과(과거 기록 날짜 허용, 미래/잘못된 형식 및 실제 생성 시각 위조 거부)
- 기존 알림 서버 테스트 12개 통과
- 날짜 경계의 독립 Dart 검사 통과

실제 iOS 코드 서명/아카이브, 기기 설치, 운영 규칙 배포는 수행하지 않았습니다.
